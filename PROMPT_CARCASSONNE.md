# Промт для вайбкодинга игры «Каркассон»

Создай полноценную браузерную настольную игру в духе классического «Каркассона»: пошаговую стратегию с выкладыванием квадратных тайлов, дорогами, городами, монастырями и фишками игроков. Игра должна поддерживать как локальную игру за одним компьютером, так и онлайн-мультиплеер.

## Технологии

- Клиент: React + TypeScript + Vite.
- Стили: Tailwind CSS или CSS Modules.
- Локальное состояние: Zustand либо React Context + `useReducer`.
- Сетевой сервер: Node.js + TypeScript, Express/Fastify и Socket.IO или WebSocket.
- Для MVP допустимо хранить комнаты и состояние партии в памяти сервера; архитектура должна позволять позднее подключить БД (например, PostgreSQL).
- Не используй оригинальные логотипы, иллюстрации и прочие защищённые ассеты. Нарисуй тайлы программно через HTML/CSS/SVG/Canvas в собственном нейтральном стиле.
- Код должен быть чистым, типизированным, разбитым на компоненты и легко расширяемым.

## Цель MVP

Сделай игру для 2–4 игроков. Должны быть два режима:

1. **Локальная партия** — игроки ходят по очереди за одним компьютером.
2. **Онлайн-партия** — один игрок создаёт комнату, получает короткий код или ссылку-приглашение, остальные подключаются из браузера. Игра идёт синхронно в реальном времени.

Игроки по очереди:

1. Берут случайный тайл из колоды.
2. Вращают его.
3. Размещают на поле по правилам совместимости сторон.
4. При желании ставят одну фишку на объект тайла.
5. Передают ход следующему игроку.
6. В конце получают очки за завершённые и незавершённые объекты.

## Сетевой режим

- Экран создания или входа в комнату: «Создать игру», «Присоединиться по коду», поле имени игрока.
- Создатель комнаты становится хостом и выбирает число игроков (2–4), имена и параметры партии.
- Комната отображает код, ссылку-приглашение, список подключённых игроков и их статус готовности.
- Хост может начать игру, когда подключилось нужное число игроков; при желании добавь настройку «разрешить начать неполным составом».
- Сервер является единственным источником истины: он хранит колоду, поле, активного игрока, фишки, очки и журнал ходов.
- Клиент отправляет намерения (`rotateTile`, `placeTile`, `placeMeeple`, `skipMeeple`), а сервер проверяет правила и рассылает обновлённое состояние всем участникам.
- Не доверяй клиенту: сервер обязан валидировать, что ход делает активный игрок, позиция допустима, тайл соответствует текущему, а фишка ставится только на разрешённый объект.
- Добавь переподключение: игрок после обновления страницы может вернуться в партию по сохранённому токену/идентификатору сессии.
- При временном отключении показывай статус «Нет соединения, пытаемся переподключиться». Когда игрок отключён, игра может ждать его или продолжаться по настройке хоста.
- Новые зрители могут наблюдать за партией без права хода (необязательно для MVP, но архитектуру стоит предусмотреть).
- Все игроки должны видеть одинаковое поле, текущий тайл, журнал, счёт и индикатор активного игрока без ручного обновления страницы.
- Добавь понятные события сокетов: `roomCreated`, `roomJoined`, `roomUpdated`, `gameStarted`, `gameState`, `actionRejected`, `playerDisconnected`, `gameFinished`.
- Ошибки правил должны отображаться игроку в виде понятного уведомления, а не ломать игру.

## Игровое поле

- Поле бесконечное, с камерой: перетаскивание мышью/тачпадом и масштабирование колесом.
- В начале в центре лежит стартовый тайл.
- Каждый тайл занимает одну клетку координатной сетки: `{x, y}`.
- Показывай координатную сетку только в режиме отладки, по умолчанию она скрыта.
- Размещённые тайлы должны плавно появляться.
- Свободные клетки, куда можно положить текущий тайл, подсвечивай зелёным.
- При наведении показывай красную подсветку недопустимой позиции и полупрозрачный предпросмотр на допустимой позиции.

## Типы ландшафта

Поддержи `field` (поле), `road` (дорога), `city` (город), `monastery` (монастырь в центре) и, при необходимости, `empty`.

У тайла четыре стороны: `north`, `east`, `south`, `west`.

Совместимость сторон:

- дорога соединяется только с дорогой;
- город — только с городом;
- поле — только с полем;
- если у клетки несколько соседей, все прилегающие стороны должны совпадать.

## Набор тайлов

Создай колоду примерно из 50–72 тайлов: прямые дороги, повороты, перекрёстки, дороги у города, малые и большие города, города со щитами, монастыри, поля и сложные сочетания объектов.

Используй структуру данных, которую можно расширять:

```ts
type Terrain = "field" | "road" | "city";

type TileDefinition = {
  id: string;
  sides: { north: Terrain; east: Terrain; south: Terrain; west: Terrain };
  center?: "monastery";
  roadConnections?: Array<["north" | "east" | "south" | "west", "north" | "east" | "south" | "west"]>;
  citySegments?: string[][];
  shields?: number;
  copies: number;
};
```

Продумай связи сегментов так, чтобы можно было корректно определять объединённые дороги и города.

## Вращение тайла

- Игрок может вращать текущий тайл до размещения.
- Добавь кнопку поворота на 90° по часовой стрелке и горячую клавишу `R`.
- Тайл в предпросмотре поворачивается анимированно.
- После поворота сразу пересчитывай допустимые позиции.

## Фишки игроков

У каждого игрока: имя, цвет, запас из 7 фишек, очки и количество доступных фишек.

Цвета по умолчанию: красный, синий, зелёный, жёлтый.

После размещения тайла игрок может пропустить размещение фишки или поставить её на разрешённую дорогу, город либо монастырь нового тайла. Нельзя ставить фишку на связанную структуру, где уже есть фишка любого игрока. Заложи архитектуру для будущего добавления фишек на поля.

## Подсчёт очков

### Дорога

Дорога завершена, когда закрыты все её открытые концы. Она приносит 1 очко за каждый тайл дороги. Очки получают игроки с наибольшим числом фишек на дороге; при ничьей все лидеры получают полные очки. Затем фишки возвращаются владельцам.

### Город

Город завершён, когда не имеет открытых городских граней. Он приносит 2 очка за каждый тайл и 2 очка за каждый щит. В конце игры незавершённый город приносит 1 очко за тайл и 1 за щит. После завершения фишки возвращаются владельцам.

### Монастырь

Монастырь завершён, если заняты все 8 соседних клеток. Он приносит 9 очков. В конце игры: 1 очко за монастырь и каждую заполненную клетку вокруг.

## Конец игры

Игра заканчивается, когда колода пуста и завершён последний ход. Покажи модальное окно с рейтингом, очками, оставшимися фишками, победителем (или победителями при ничьей) и кнопкой «Начать заново».

## Интерфейс

Сделай современный тёплый интерфейс настольной игры:

- фон с CSS-текстурой дерева или мягкий однотонный;
- светлые картонные тайлы с тенями и скруглением 6–10px;
- дороги песочного цвета, поля зелёные, города каменные с приглушёнными терракотовыми акцентами;
- фишки — заметные цветные SVG-фигурки;
- слева или снизу — карточки игроков, очки и фишки;
- справа — текущий тайл, поворот и кнопка пропуска фишки;
- сверху — ход, остаток колоды, кнопки «Новая игра», «Правила», «Отменить ход»;
- в онлайне добавь код комнаты, индикатор соединения и статусы игроков.

Адаптируй интерфейс для ширины от 1280px и планшетов.

## Состояния хода

Явно реализуй конечный автомат:

```ts
type TurnPhase =
  | "drawingTile"
  | "placingTile"
  | "placingMeeple"
  | "scoring"
  | "gameOver";
```

Последовательность: взять тайл → повернуть и разместить → проверить завершённые объекты → поставить фишку или пропустить → начислить очки → передать ход.

## Дополнительные требования

- Журнал последних действий: «Анна разместила тайл», «Илья получил 6 очков за город».
- Отмена последнего действия допустима только в пределах текущего хода и только до подтверждения действия сервером/перехода хода; в онлайне сервер валидирует откат.
- Сохраняй локальную партию в `localStorage`.
- Онлайн-партия должна восстанавливаться после перезагрузки через сервер и токен игрока.
- Добавь экран создания партии с количеством игроков и редактируемыми именами.
- Добавь встроенную краткую справку с правилами.
- Добавь режим разработчика: ID тайлов, координаты и связи объектов.
- Добавь unit-тесты для допустимости размещения, поворота сторон, завершения дороги/города, начисления очков и заполнения монастыря.
- Добавь интеграционные тесты сетевого слоя: вход в комнату, невозможность сделать ход не в свою очередь, синхронизация размещённого тайла между двумя клиентами и переподключение игрока.

## Критерии готовности

- Можно начать локальную или сетевую партию на 2–4 игроков.
- Игроки подключаются в комнату по коду или ссылке и видят синхронное состояние.
- Тайлы корректно вращаются и размещаются только по правилам.
- Сервер не позволяет подделать ход или поставить фишку на занятую связанную структуру.
- Дороги, города и монастыри корректно завершаются, начисляют очки и возвращают фишки.
- Игра заканчивается после исчерпания колоды.
- Локальная партия сохраняется в браузере; сетевой игрок может восстановить соединение.
- Проект запускается командами:

```bash
npm install
npm run dev
```

Сначала создай рабочий MVP с корректной игровой и сетевой логикой, затем улучши визуализацию, анимации и удобство интерфейса.
