# Земли и замки

Учебный MVP браузерной настольной стратегии по ТЗ из `PROMPT_CARCASSONNE.md`: локальная игра и онлайн-комнаты на 2–4 игроков. Клиент — React, TypeScript, Vite и CSS Modules; сервер — Express и Socket.IO. Все иллюстрации тайлов и фишек рисуются собственным SVG-кодом.

## Быстрый запуск

При установленном Node.js 22.12+:

```powershell
npm install
npm run dev
```

Откройте **http://localhost:5173**. Клиент работает на порту 5173, игровой сервер — 3001; Vite проксирует сокеты и `/api`.

Если Node.js отсутствует в PATH, но установлен Codex, используйте подготовленный скрипт из этой папки:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт ищет системный Node.js или встроенный runtime Codex. При необходимости скачивает npm из официального реестра, проверяет SHA-512 архива и устанавливает зависимости. Кеш остаётся в `.tools/`, глобальные настройки Windows не меняются. Если нет ни одного runtime, установите Node.js и воспользуйтесь обычными командами выше. Для остановки сервера нажмите Ctrl+C.

## Как сыграть

1. Выберите локальный режим, число игроков и имена. Либо создайте онлайн-комнату и отправьте друзьям её ссылку или шестизначный код.
2. В комнате каждый нажимает «Я готов(а) играть», после чего создатель запускает партию. По умолчанию нужен полный состав; при создании можно разрешить старт от двух игроков.
3. Поворачивайте тайл кнопкой или клавишей **R**. Нажмите зелёную клетку для размещения. Несовместимые стороны запрещены.
4. Нажмите «+» на объекте нового тайла, чтобы поставить фишку, либо пропустите. До этого решения тайл можно переложить кнопкой отмены.
5. Завершённые объекты начисляют очки и возвращают фишки. Последний ход запускает финальный подсчёт и таблицу результатов.

Поле перетаскивается мышью или касанием, колесо меняет масштаб. «Всё поле» возвращает камеру ко всем размещённым тайлам. Режим разработчика показывает сетку, ID, координаты и связи объектов. Краткие правила доступны внутри игры.

Для двух игроков на одном компьютере используйте **разные браузеры или обычное и приватное окно**. Вкладки одного профиля разделяют токен в localStorage и после перезагрузки восстанавливают одного и того же игрока. Локальную партию лучше вести в одной вкладке.

### Игра в одной сети

Остальные устройства должны открыть один и тот же адрес компьютера с сервером, например `http://192.168.1.127:5173`. Точный Network URL печатает Vite. Создавайте комнату через этот адрес, чтобы ссылка-приглашение также содержала доступный друзьям адрес. `localhost` на другом устройстве указывает на само это устройство.

Для демонстрации через интернет нужен общий доступный сервер с поддержкой WebSocket. Публикация и настройка внешнего доступа не выполнялись.

## Проверка и сборка

```powershell
npm test
npm run build
npm start
```

Production-сборка отдаёт клиент и Socket.IO с одного адреса: **http://localhost:3001**. Порт задаётся переменной `PORT`. Запускайте команды из корня проекта.

Альтернатива проверки для текущего Windows-окружения:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Check
```

Тесты покрывают поворот, совместимость со всеми соседями, разделённые сегменты, завершение дорог и городов, щиты, большинство и ничьи, запрет занятого объекта, монастыри, последний ход, десять полных партий с сохранением числа тайлов и фишек, а также комнаты, серверную валидацию, синхронизацию двух клиентов, откат и переподключение.

## Уточнения к исходному ТЗ

ТЗ выполнимо как демонстрационный MVP при следующих конкретных решениях:

- Порядок хода: взять тайл → повернуть и разместить → поставить фишку или пропустить → начислить очки → передать ход. Проверка завершения не начисляет очки до выбора фишки: игрок может занять объект, который только что завершил своим тайлом.
- В колоде 60 тайлов, включая стартовый. Это собственный сбалансированный для демонстрации набор из 16 определений, а не точное воспроизведение официальной колоды.
- Каждая ветвь дороги заканчивается на перекрёстке. Раздельные городские сегменты не соединяются внутри тайла. Щиты принадлежат конкретному городскому сегменту.
- Если тайл нельзя разместить ни в одном из четырёх поворотов, он сбрасывается автоматически. Когда подходящих тайлов больше нет, выполняется финальный подсчёт.
- Отмена размещения разрешена **в текущем ходу до фишки или пропуска**, в том числе после принятия размещения сервером. Это устраняет неоднозначность требования «только до подтверждения сервером»: в авторитетной модели подтверждение приходит практически сразу. После передачи хода откат невозможен.
- При отключении активного онлайн-игрока партия ждёт его возвращения. Автоматического пропуска нет.

## Границы MVP

- Комнаты и токены находятся в памяти сервера. Обновление браузера восстанавливает игрока, **перезапуск сервера удаляет онлайн-партии**. Неактивные комнаты очищаются после 24 часов без подключённых участников.
- Локальная партия, включая доступный откат, сохраняется в localStorage. Если браузер запрещает запись, играть можно, но сохранение недоступно. Онлайн-токен привязан к текущему адресу и профилю браузера.
- Фермеры и очки за поля, зрители, боты, таймеры, чат, расширения, аккаунты и БД не входят в MVP.
- Это прототип для доверенной учебной группы: есть проверка ходов, ограничение размера сообщения и частоты действий на сокет, но нет полноценной защиты публичного сервиса от злоупотреблений, системы восстановления потерянного токена и управления покинутыми местами.
- Производственная сборка и автоматические тесты проверены. Визуальная проверка через браузер не завершена: инструмент компьютерного управления остановился, поскольку не смог надёжно определить текущий URL Chrome. Перед показом стоит пройти ручной сценарий ниже.

## Ручная проверка перед показом

- Начать локальную игру на 2 и 4 игроков; повернуть тайл кнопкой и R; проверить предпросмотр, размещение, фишку, пропуск и отмену.
- Перетащить и масштабировать поле; открыть правила и режим разработчика; проверить планшетную ширину.
- Обновить страницу после размещения тайла и продолжить сохранённый ход.
- Создать комнату, войти из другого браузера, подтвердить готовность и начать игру. Сравнить поля и счёт.
- Обновить страницу активного сетевого игрока, затем временно отключить его и проверить восстановление.

## Структура проекта

```text
shared/types.ts      Общие типы, действия и состояния фаз
shared/tiles.ts      Расширяемый каталог тайлов и сегментов
shared/engine.ts     Чистый движок, граф объектов, подсчёт очков
server/rooms.ts      Модель комнаты и интерфейс хранилища
server/app.ts        Валидация намерений, сокеты и сессии
server/index.ts      Запуск сервера
src/useGame.ts       Локальный reducer, сохранение и сетевой клиент
src/Tile.tsx         SVG-ландшафт и фишки
src/Board.tsx        Камера, подсветка и размещение
src/App.tsx          Создание партии, лобби, игровой экран и результаты
src/App.module.css   Оформление и адаптивные раскладки
tests/              Тесты движка и интеграция Socket.IO
```

`GameState` хранит закрытую колоду. Клиенты онлайн получают `GameView` без порядка колоды и без чужих токенов. Клиент отправляет намерения; сервер сам выбирает текущий тайл, проверяет очередь, координаты, фазы и занятость связанного объекта. Переходы `drawingTile` и `scoring` выполняются атомарно внутри движка, промежуточные состояния не рассылаются.

Для подключения PostgreSQL предусмотрен интерфейс `RoomRepository`. При переходе к БД нужно также сохранять токены сессий, писать изменения транзакционно и согласовывать операции между несколькими процессами сервера.

События клиента: `createRoom`, `joinRoom`, `setReady`, `startGame`, `gameAction`, `restartGame`. Действия внутри `gameAction`: `rotateTile`, `placeTile`, `placeMeeple`, `skipMeeple`, `undo`.

События сервера: `roomCreated`, `roomJoined`, `roomUpdated`, `gameStarted`, `gameState`, `actionRejected`, `playerDisconnected`, `gameFinished`, `sessionExpired`. Доступность сервера: `GET /api/health`.
